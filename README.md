以下是针对《45. 跳跃游戏 II》这道题的详细拆解：

### （1）用白话文解释题目意思及生僻概念

**题目白话文解释：**
这同样是一个“跳格子”游戏，起点在第 1 个格子（下标为 0）。每个格子上的数字代表从当前位置**最多**能向后跳几步。与上一题（判断能不能到达终点）不同，这道题明确告知**一定能到达终点**。现在的目标是：找出一条路径，使得跳跃的**次数最少**。用最少的步数通关。

**生僻概念解释：**

  * **0 索引整数数组**：计算机编程中的常见叫法，意思是数组的第一个元素的位置记为 0，第二个记为 1，依此类推。
  * **最小跳跃次数**：达到终点可能有多种跳法。比如示例中 `[2,3,1,1,4]`，可以按 `2 -> 1 -> 1 -> 4` 跳 3 次，也可以按 `2 -> 3 -> 4` 跳 2 次。需要寻找并返回那个最小的数字（2次）。

### （2）解题思路的来源（基于代码反推）

这段代码采用的是**贪心算法**，核心思路可以形象地比喻为\*\*“走到黑再建桥”\*\*。

1.  **延迟跳跃决策**：要想跳跃次数最少，每一次跳跃都应该尽可能地覆盖更远的距离。但站在当前位置时，往往不知道到底跳到后面哪个格子最划算。
2.  **探索与记录**：既然不知道跳到哪里最好，那就先不急着跳。而是在当前这一步能够到达的范围内（即当前这座“桥”上），一步步往前走，每走一步都往远处张望一下，看看“如果从这里起跳，最远能跳到哪里”，并把这个**最远能跳到的位置**记录下来（记录为下一座桥的终点）。
3.  **被迫起跳**：当走到当前这座“桥”的尽头时（也就是实在走不下去了，必须得跳了），就别无选择了，必须消耗一次跳跃次数。此时，直接把前面记录的那个“最远能跳到的位置”作为新的边界，继续往前走。
4.  **提前结束遍历**：因为目标只是到达最后一个位置，所以不需要走到最后一个格子上再去判断。只要走完了倒数第二个格子，就可以确定最终需要的跳跃次数。

### （3）每一行代码的注释

```python
class Solution:
    def jump(self, nums: List[int]) -> int:
        ans = 0                         # 记录跳跃的次数，初始为 0
        cur_right = 0                   # 记录当前这次跳跃能够到达的最远边界（当前桥的右端点）
        next_right = 0                  # 记录在当前边界内遍历时，下一步所能到达的最远位置（下一座桥的右端点）
        for i in range(len(nums) - 1):  # 遍历数组，直到倒数第二个元素
            next_right = max(next_right, i + nums[i])  # 走到位置 i 时，计算并更新下一步能到达的最远距离
            if i == cur_right:          # 如果走到了当前这次跳跃的边界（当前桥走到了尽头）
                cur_right = next_right  # 必须跳跃了，把边界更新为刚才记录的最远位置（踏上下一座桥）
                ans += 1                # 跳跃次数加 1
        return ans                      # 返回总跳跃次数
```

### （4）每一行代码的详细中文解释

  * `class Solution:`
      * 定义封装解题算法的类。
  * `def jump(self, nums: List[int]) -> int:`
      * 定义函数 `jump`，接收一个名为 `nums` 的整数列表，并指明最终返回一个整数（最少跳跃次数）。
  * `ans = 0`
      * 初始化变量 `ans`（answer的缩写），用来累计跳跃的次数。最开始还在起点，没跳过，所以是 0。
  * `cur_right = 0`
      * 初始化当前能到达的最远边界。起点在下标 0，在没有进行第一次跳跃前，只能在下标 0 这个位置活动。
  * `next_right = 0`
      * 初始化“下一步的最远潜力”。随着在当前边界内向右移动，这个变量会不断更新，记录下能够探测到的最远位置。
  * `for i in range(len(nums) - 1):`
      * 开启循环，遍历数组。注意范围是到 `len(nums) - 1`（不包含最后一个元素）。因为如果 `cur_right` 刚好覆盖到最后一个元素，再往下走就会多算一次不必要的跳跃；如果走到倒数第二个元素时还没有到达终点，那么必然要在倒数第二个元素及之前起跳一次才能到达终点。因此，只遍历到倒数第二个位置足够做出所有决策。
  * `next_right = max(next_right, i + nums[i])`
      * 核心更新逻辑：当前处于下标 `i`，格子上的数字是 `nums[i]`，说明从这里起跳最远能到 `i + nums[i]`。用 `max` 函数将其与之前记录的 `next_right` 进行比较，保留数值更大的那一个。
  * `if i == cur_right:`
      * 核心判断逻辑：检查当前走到的位置 `i` 是否已经到达了当前跳跃能覆盖的极限边界 `cur_right`。
  * `cur_right = next_right`
      * 如果上面的判断成立（到达了边界），说明必须进行一次真正的跳跃了。此时，将接下来能够活动的范围边界更新为之前一路探测到的最远位置 `next_right`。
  * `ans += 1`
      * 因为被迫发生了一次跳跃，所以将跳跃次数累计加 1。
  * `return ans`
      * 循环结束后，所有必要的跳跃都已经计算完毕，返回记录的总跳跃次数。
